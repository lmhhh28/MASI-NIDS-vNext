## 使用规则

本登记只记录官方规范、项目官方文档或标准组织资料。上游网页中的 `latest/current/stable` 是评估日事实，不是 MASI-NIDS 自动升级授权；项目实际兼容性由 `contracts/profiles/v1`、ADR 和资格证据决定。

含 `latest`、`next`、`current`、GitHub branch 或持续更新页面的 URL 只属于调研入口，不是可复现资格证据。模块启动实现前，每个采用事实必须在 `contracts/profiles/v1`/`contracts/supply-chain/v1` 分配稳定`source_id`，记录访问日期、页面标题、可取得的 exact release/tag/commit、可复核archive snapshot/digest、实际 package/image/binary digest、许可证和 evidence；无法冻结的来源或制品保持 `HOLD`。本登记是调研索引，不冒充未来机器可读source registry，也不会为了制造“已冻结”外观而虚构上游 commit。

引用分为：

- **Normative upstream**：项目声称实现该协议/格式时必须对照；
- **Mature pattern**：只借鉴模式，不整体引入产品或控制面；
- **Operational guidance**：为具体边界、故障或证据提供实现依据。

## 未被来源授权的结论

以下内容不能仅凭上述来源声称：

- MASI-NIDS 已实现、已通过 E2E 或达到生产资格；
- 某一 Wasmtime/OpenAPI/SDK 新版本因“stable/latest”自动兼容；
- 签名、SBOM 或 provenance 证明插件功能正确或安全；
- Pact/contract test 代替 schema、fault、performance 或 full E2E；
- P4Runtime primary 成功自动证明 application generation、pipeline 和历史 evidence 仍有效；
- PostgreSQL HA 配置存在自动证明 RPO/RTO/PITR restore 已通过。
- 1Panel/sub2api 的技术栈成熟自动授权复制其应用源码、CSS、资产、品牌、权限或控制面；
- MIT/Apache/LGPL/GPL 的仓库级标签自动覆盖每个 example、theme、icon、font、generated template 或传递依赖；
- 使用成熟 UI library 自动满足 MASI-NIDS 的 exact P4 diff、HOLD/unknown、maker-checker、WCAG、性能或安全门禁。
- P4 direct counter 增长自动证明 action 成功、攻击已阻断或 Incident 风险下降；
- zero hit 自动证明规则无效/冗余/可删除，或没有 eligible traffic 时可以显示 0%；
- PTF/P4Testgen/BMv2 PASS 自动证明真实硬件 target 的 counter、byte、reset、性能或 outcome 已资格化；
- Prometheus/Grafana/Alertmanager/OTel 中的值、silence、annotation 或 Action 可以替代 PostgreSQL rule fact、Go authorization 或 Edge P4 path；
- OpenTelemetry metric、Grafana data frame、ECharts dataset、Backstage extension 或 Vega interpreter 的成熟度自动授权把其完整 wire/UI/runtime schema 暴露给插件，或允许插件业务统计绕过 Go 校验、PostgreSQL 投影与浏览器 CSP；
- 插件统计 Artifact 可以覆盖 Rule Effectiveness/Event/Incident canonical fact、被浏览器直接执行，或因“只读”而获得核心数据库/Prometheus/P4凭据、自行轮询和调度；
- Patroni/pgBackRest/PgBouncer 配置存在自动证明 PostgreSQL HA/PITR/RPO/RTO；
- Buf/Syft/Trivy/Cosign 任一工具 PASS 自动证明 wire compatibility、许可证、安全、功能或生产资格；
- “成熟方案”可以绕过 exact version/digest、供应链登记、故障/性能/兼容/退出门禁，或取得第二事实源、第二 P4 writer、第二 effect queue。
- ONNX metadata、MLflow signature/alias、Triton repository/version policy、KServe/Kubernetes Ready/route 或一个模型质量分可以替代 `contracts/model/v1`、Go/PostgreSQL per-shard exact binding、Gateway pool readback、current/previous compatibility 或项目资格证据。
- 新 model/label/confidence 可以自动继承旧 deterministic policy/effect eligibility，或 shadow/canary 输出可以直接写 canonical Event/Incident/Proposal/Decision/Intent。
- ORT/Triton/TF Serving/Kubernetes 支持某种 load/rolling/Ready 能力，就自动证明 MASI-NIDS 可以启用进程内热切换、零中断或绕过 Go/PostgreSQL readback/CAS；上游能力不是项目资格。
- Kubernetes `maxSurge`、PDB、PreStop或Ready可以单独证明rolling容量、已drain、旧实例已终止或不会双路由；terminating资源、hook重复/超时和workload rollout必须由项目profile与故障证据覆盖。
- offline optimized model文件存在就自动兼容当前ORT/EP/options/device/CPU，或不兼容时可以静默fallback到online optimization；optimization与thread/arena默认必须是exact profile的一部分。
- Tcpreplay返回成功或报告发送包数自动证明 test ingress/BMv2/DUT收到、规则命中、action正确或模型检测成功；这些是独立 observation。
- 二层 PCAP replay自动建立 TCP handshake、重传、拥塞控制或应用会话；需要这些语义必须使用受控 live-session endpoint/stateful profile。
- Mininet/BMv2 requested或achieved PPS自动代表硬件 ASIC、真实 NIC、line rate或生产容量；software/hardware target必须分别资格化。
- CIC-IDS2017、UNSW-NB15、CTU等公开可下载或要求论文引用，就自动允许任意用途、再分发、进入仓库/镜像，或其 flow label可无验证成为 packet truth。
- CIC-DDoS2019允许再分发就自动消除payload隐私、ground-truth join、retention、下载artifact digest、六维P4重提取和目标分布资格；许可只是一个门禁。
- 旧MASI-NIDS dataset目录已有CSV/NPY或模型就自动证明其来源、许可、split、feature语义和vNext资格；legacy 21/38/80列不得直接补零/重命名成六维线上输入。
- XGBoost/ONNX Runtime/InterpretML/PyTorch官方支持某种模型或解释方法，就自动证明该exact graph能在pinned Triton/ORT CPU/CUDA运行、满足`[N,2]`输出、数值/性能/供应链门禁，或授权custom operator/fallback。
